# СПИКЕР

СПИКЕР — локальное приложение для распознавания аудио- и видеофайлов и диктовки с микрофона.

## Где находятся код и модели

В проекте это разные вещи, поэтому буквально объединять каталоги `scripts/model` и `models` нельзя: первый содержал Python-код распознавания, а второй хранит загружаемые веса нейросетей. Чтобы не путать их, код обработки переименован в `scripts/transcription/`.

Все веса теперь собраны в одном корневом каталоге:

```text
models/
  whisper/   # модели Whisper: ggml-*.bin
  vosk/      # модели Vosk: папки моделей
```

Если в старой установке модель Vosk находится по адресу `model/vosk-model-small-ru-0.22`, СПИКЕР при запуске попытается перенести именно эту папку в `models/vosk/`. Перенос выполняется переименованием каталога на том же диске; если это невозможно, старый путь остаётся рабочим. Другие файлы в `model/` не удаляются.

## ИИ-обработка расшифровок (СПИКЕР 3.0.2)

На главном экране откройте третью карточку **«ИИ-обработка»** или в очереди нажмите **«Обработать с ИИ»** возле результата. Доступны локальный ИИ через Ollama и дополнительный OpenAI-совместимый API. Локальный режим по умолчанию использует `http://127.0.0.1:11434/v1` и не отправляет текст внешнему API. Сам СПИКЕР не скачивает языковые модели.

Для первоначальной подготовки модели откройте [AI_SETUP.md](AI_SETUP.md) или запустите `Prepare_Local_AI.bat` после установки Ollama. Скрипт явно загрузит `qwen3.5:4b`; затем проверьте соединение и список моделей в панели ИИ. После этого модель можно использовать без интернета.

ИИ умеет корректировать оформление расшифровки, делать краткое содержание или конспект, составлять протокол, извлекать задачи и отвечать на вопросы. Длинный текст обрабатывается фрагментами. Оригинал остаётся отдельным; ИИ-результаты автоматически сохраняются в `results/ai/` и экспортируются в Markdown, TXT или JSON. Перед внешним API-запросом СПИКЕР спрашивает подтверждение, а ключ хранится через системное хранилище учётных данных, если оно доступно.

Экспорт завершённых транскрибаций расширен до TXT, Markdown, SRT, VTT, JSON и DOCX. Для SRT/VTT используются реальные временные отметки сегментов Whisper; если сегментов с таймкодами нет, приложение не создаёт приблизительные субтитры.

Полное зафиксированное ТЗ — [SPEC_Spiker_3.0.md](SPEC_Spiker_3.0.md); условия локального режима и устранение ошибок — [AI_SETUP.md](AI_SETUP.md).

**Аппаратное примечание:** под целевую конфигурацию 16 ГБ ОЗУ и 8–12 ГБ VRAM рекомендуем начать с компактной квантованной модели. Реальный расход памяти зависит от версии модели, квантования, контекста и драйвера. Текущий Whisper backend работает в CPU-режиме; Ollama может использовать GPU для языковой модели при корректной конфигурации.

## Работа с файлами и аудиоплеер

1. Нажмите **«Загрузить файл»** и добавьте один или несколько файлов. Можно также перетащить их в очередь.
2. Слева показывается очередь с именем файла, длительностью аудиодорожки, размером, форматом и статусом. Файл сразу появляется в списке; метаданные и волна анализируются в фоне.
3. Выбор файла обновляет правую панель плеера. После обнаружения аудиодорожки можно начать прослушивание, даже если полная волна ещё рассчитывается.
4. Управление включает воспроизведение/паузу, стоп, перемотку ±10 секунд, ползунок позиции, громкость и скорость. Нажатие на волну и перетаскивание курсора также меняют позицию.
5. Кнопка **«Обновить волну»** принудительно пересчитывает форму сигнала. Волна строится из реальных PCM-данных, а не из декоративных столбцов.
6. Анализ волны кэшируется в `data/waveform_cache/`. Ключ учитывает путь исходного файла, размер, время изменения и параметры расчёта; повторное открытие неизменённого файла обычно использует кэш.
7. Нажмите **«Очередь»** для транскрибации. Во время работы доступны разные операции: **«Пауза»** временно приостанавливает работу на границе сегмента; **«Остановить и сохранить»** завершает текущий запуск, сохраняя распознанный текст и точку продолжения; **«Отменить задачу»** сбрасывает контрольную точку; **«Удалить из списка»** убирает запись из очереди, но не удаляет исходный файл с диска.
8. Чтобы продолжить после остановки, нажмите **«Очередь»** снова или выберите задачу и нажмите **«Продолжить / повторить»**. СПИКЕР сохранит уже распознанные сегменты и возобновит распознавание около последней контрольной точки, с небольшим перекрытием для сохранения контекста. При первом повторном запуске MP3/MP4 аудио может заново подготавливаться перед возобновлением распознавания.
9. Готовый текст можно проверить, отредактировать и сохранить как TXT. Ошибочную задачу можно повторить.

Очередь хранится в `data/queue.json`, кэш амплитуд — в `data/waveform_cache/`, готовые результаты — в `results/`. Удаление строки убирает элемент из списка, но не удаляет исходный файл с диска. Повторные пути в одной очереди не дублируются.

## Диктовка в реальном времени

При выбранной модели Whisper запись поступает в распознаватель окнами примерно по 2 секунды с 1-секундным акустическим перекрытием, чтобы уменьшить разрывы на границах фраз. Текст интерфейса обновляется по мере того, как whisper.cpp декодирует отдельные речевые сегменты, а не только после окончания всей записи. Повторные слова в зоне перекрытия удаляются по совпадающему суффиксу/префиксу. Задержка всё равно зависит от скорости выбранной модели и CPU; для максимально быстрой диктовки используйте Small/Base/Tiny. При наличии полной модели Vosk приложение автоматически использует её потоковые промежуточные гипотезы, которые обычно появляются с меньшей задержкой.

Если установлена полная модель Vosk, приложение автоматически использует его `PartialResult()` — промежуточную гипотезу, обновляющуюся почти сразу по мере поступления аудио. Если Vosk неполный, используется Whisper. Whisper-файл и микрофонная диктовка используют отдельные контексты модели и могут работать одновременно. Это увеличивает потребление памяти: при Medium в обеих задачах может понадобиться существенно больше ОЗУ. Для диктовки обычно лучше выбрать Small, Base или Tiny, если такая модель установлена.

## Остановка, отмена и возобновление

- **Пауза** удерживает текущую задачу на ближайшей границе сегмента Whisper; очередь остаётся активной.
- **Остановить и сохранить** прекращает текущую задачу безопасно, переводит её в «Приостановлено» и сохраняет последний распознанный текст, процент и время аудио последнего подтверждённого сегмента.
- **Очередь** возобновляет приостановленную задачу с сохранённой контрольной точки. Для продолжения остаётся небольшой перекрывающийся аудиофрагмент, чтобы не обрезать слова; повторяющиеся слова на стыке объединяются.
- **Отменить задачу** сбрасывает промежуточный текст и контрольную точку; повторный запуск начнёт сначала.
- **Удалить из списка** удаляет задачу из очереди, но не затрагивает исходный аудио-/видеофайл. Активную задачу сперва нужно остановить или отменить.
- Если приложение закрыто или аварийно завершилось, последняя сохранённая контрольная точка восстанавливается при следующем запуске, если она уже была записана после распознанного сегмента.

## Модели и настройки

Нажмите значок настроек в верхней части главного экрана. СПИКЕР ищет модели Whisper `.bin` внутри папки `models` и её подпапок. Список — это кандидаты по расширению и размеру, не автоматическая гарантия совместимости.

Рекомендуемое расположение:

```text
models/
  whisper/
    ggml-small.bin
    ggml-medium.bin
    ggml-base.bin
    ggml-tiny.bin
  vosk/
    vosk-model-small-ru-0.22/
```

Оставьте на диске только нужные модели: архив не включает большие веса и не скачивает их автоматически. Настройки позволяют выбрать модель для файлов и отдельную модель для диктовки, язык речи и число CPU-потоков.

### Как выбрать число потоков

Начните с 3–4 CPU-потоков; на слабом компьютере попробуйте 2. Потоки — это вычислительные рабочие потоки внутри одного распознавателя, а не число параллельных файлов. Слишком много потоков может замедлить систему, потому что процессы конкурируют за CPU и память. Скорость также зависит от выбранной модели, длины файла, кодека, шума в записи и аппаратной поддержки.

Small/Base/Tiny обычно работают быстрее и занимают меньше памяти. Medium часто даёт более качественный результат, но требует больше времени и памяти. Модель загружается при первом использовании конкретного режима и остаётся в памяти, пока приложение открыто.

### Какие модели поддерживаются

Текущая реализация использует `whisper.cpp` через `pywhispercpp` и совместимые локальные модели Whisper, обычно файлы `ggml-*.bin`. Простое копирование модели другого семейства в папку `models` не подключает её автоматически.

Например, `faster-whisper` использует движок CTranslate2 и отдельный формат моделей, поэтому для него нужно добавить отдельный backend/адаптер. См. [официальный проект faster-whisper](https://github.com/SYSTRAN/faster-whisper) и [pywhispercpp](https://github.com/absadiki/pywhispercpp). Сейчас этот релиз не содержит backend faster-whisper, ONNX или новых сторонних движков.

## Прослушивание и звуковая волна

В очереди выберите файл, чтобы его прослушать, остановить воспроизведение или переместиться по дорожке. Кнопка **«Построить волну»** создаёт амплитудную визуализацию в фоновом потоке. Высокие участки означают более сильный звук, низкие — возможную тишину. Это огибающая громкости, не частотный спектр и не гарантированный детектор речи.

Поддержка конкретного кодека воспроизведения зависит от мультимедийного backend Qt в Windows; если он не может воспроизвести исходный формат, транскрибация через встроенный FFmpeg может при этом по-прежнему работать.

## Аудиоплеер и кодеки

Воспроизведение использует `QMediaPlayer`/`QAudioOutput` из Qt Multimedia. Доступность конкретных контейнеров и кодеков зависит от сборки Qt и Windows. Если медиадвижок не может воспроизвести файл, СПИКЕР показывает ошибку; наличие аудиодорожки для транскрибации отдельно проверяется через поставляемый FFmpeg (`imageio-ffmpeg`). Поэтому файл может быть пригоден для транскрибации даже при ошибке его прослушивания через Qt.

Волновая форма — амплитудная огибающая: высота столбцов показывает уровень звука и помогает заметить возможную тишину. Это не частотный спектр и не точный автоматический детектор речи. Сырые аудиосэмплы не загружаются целиком в память: FFmpeg выводит PCM порциями, а в виджете сохраняется ограниченное число пиков.

## Запуск в Windows

Поддерживается Windows 10/11 x64 и Python 3.11 x64.

- Для создания ярлыков **СПИКЕР** на рабочем столе и в меню «Пуск» запустите `Create_Spiker_Shortcut.ps1` через PowerShell.
- Ярлык запускает `SpikerLauncher.vbs`; обычный запуск использует `pythonw.exe` без окна консоли.
- Первый запуск требует интернета для установки зависимостей. Детали сохраняются в `logs/install.log`.
- Для установки/восстановления вручную запустите `Launch_Spiker.bat` или `Repair_Spiker_Environment.bat`.
- Для диагностики с видимой консолью используйте `Launch_Spiker_Diagnostics.bat`.

Зависимости закреплены в `res/requirements.txt`. Модель Whisper нужно положить в `models/whisper/` и выбрать в настройках.

## Журналы

Папка `logs` создаётся автоматически:
- `application.log` — запуск и события приложения;
- `errors.log` — ошибки;
- `processing.log` — подготовка и транскрибация;
- `whisper_native.log` — сообщения нативного движка;
- `pythonw_streams.log` — вывод скрытого процесса Python;
- `install.log` — установка зависимостей;
- `launcher.log` — обычный запуск.

## Приватность и ограничения

После установки библиотек распознавание выполняется локально на компьютере. Установка или восстановление пакетов требует интернета; веса модели автоматически не скачиваются. Процент/ETA — оценка по уже обработанным сегментам и может меняться.
