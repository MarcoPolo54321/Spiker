# Расширенная локальная транскрибация СПИКЕР 3.0.8

## 1. Производительность

Откройте **Настройки → Проверить компьютер и подобрать режим**. Диагностика показывает CPU/потоки, RAM, NVIDIA GPU/VRAM и доступность CUDA для CTranslate2. Она предлагает профиль, но не является полноценным бенчмарком: реальный RTF/качество нужно измерять на одинаковых записях.

- **Авто** — CUDA, если установленный CTranslate2 видит совместимое устройство; иначе CPU.
- **CPU** — принудительно CPU, обычно INT8.
- **CUDA** — принудительная NVIDIA GPU; если runtime не готов, программа показывает ошибку.
- **INT8 / FP16 / INT8+FP16 / FP32** — формат вычислений. Поддержка зависит от GPU и движка.
- **Batch** — пакетная обработка; больший пакет может увеличить пропускную способность и расход VRAM. Для более связного контекста начните с batch 1.

При CUDA OOM в автоматическом режиме предусмотрен ограниченный повтор на CPU, если ещё не были сохранены сегменты. Если ошибка возникла после частичного результата, программа не должна молча перезаписывать уже сохранённые сегменты.

## 2. faster-whisper / CTranslate2

В GitHub Windows build включается runtime faster-whisper/CTranslate2. Модельные веса CTranslate2 устанавливаются отдельно. Подходящая структура:

```text
models/faster-whisper/small/
  config.json
  model.bin
  tokenizer.json
  ...
```

`ggml-small.bin` предназначен для Whisper.cpp и не является моделью CTranslate2. Запустите `Install_Models.bat` или `Install_Faster_Whisper.bat`, чтобы установить runtime/вес выбранной модели. В режиме Авто при отсутствии faster-whisper/локальной модели программа может использовать Whisper.cpp; принудительный выбор движка выдаёт понятную ошибку.

faster-whisper поддерживает VAD, batching и словесные timestamp. При большом batch окна декодируются независимо; batch 1 лучше для сохранения контекста предыдущего фрагмента.

## 3. Аудиопрофили и дорожки

В настройках доступны:

- **Речь** — обычные короткие/средние записи; VAD применяется согласно переключателю пользователя.
- **Совещание** — длинная разговорная запись с паузами.
- **Музыка и пение** — VAD выключен, чтобы не отбрасывать вокальные участки по речевому классификатору.
- **Сохранить звук** — без VAD и без нормализации; приоритет у исходного аудио.

Для MP4/MKV с несколькими аудиопотоками выберите индекс дорожки (0 — первая дорожка, 1 — вторая и т. д.). Если индекс не существует, FFmpeg сообщает понятную ошибку. Не используйте агрессивные фильтры для тихих согласных/окончаний слов.

## 4. Автоматическая диаризация pyannote Community-1

Диаризация запускается отдельно от ИИ и локально после установки зависимостей и весов модели.

1. Установите Python 3.11 x64 и закройте СПИКЕР.
2. Откройте [pyannote/speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1), войдите в Hugging Face и примите условия доступа.
3. Создайте персональный Read-токен на [Hugging Face settings](https://huggingface.co/settings/tokens).
4. Запустите `Install_Speaker_Diarization.bat` из папки приложения. Он устанавливает `pyannote.audio==4.0.7` в дополнительное `.venv311`, вводит токен скрыто, загружает model snapshot и проверяет реальный `Pipeline.from_pretrained` из локальной папки.
5. Перезапустите СПИКЕР и нажмите «Авто-спикеры».

Токен не сохраняется в `settings.json` и не должен попадать в Git, логи или архивы проекта. Модель требует принятия условий Hugging Face и не включается в публичный Setup. После загрузки модель можно использовать локально. [Официальная карточка модели](https://huggingface.co/pyannote/speaker-diarization-community-1) описывает downmix/resample и выдаёт обычную и exclusive-диаризацию.

В 3.0.8 назначение говорящего делается только при достаточном временном перекрытии; программа не должна выбирать «ближайшего» участника при отсутствии совпадения. Если доступны word timestamps, один распознанный сегмент может быть разделён по границе слова при смене голоса. Сохраняются overlap-кандидаты и неуверенные интервалы как «Не определён».

Примечание по остановке: приложение проверяет cancel между этапами диаризации, но активный native inference pyannote в середине вызова Pipeline пока не может быть гарантированно прерван. При нажатии отмены текущий вызов должен завершиться до корректного возврата управления.

## 5. Контекстный словарь и качество

В настройках добавьте имена, названия организаций, технические термины и аббревиатуры через контекстный словарь. Подсказка передаётся faster-whisper как initial prompt, но не гарантирует правильное распознавание каждого редкого слова.

Для русской речи нужно проверять Small/Medium/Large-v3 Turbo/Large-v3 на одной и той же контрольной коллекции. Forced alignment / WhisperX не включён в 3.0.8; это отдельная следующая задача с проверкой русскоязычной модели aligner. Субтитры используют реальные временные метки сегментов; словесные timestamp faster-whisper сохраняются в структуре сегментов.

## 6. Участники, редактор и экспорт

ID говорящего хранится отдельно от переключателя видимости. Переименование профиля распространяется на все сегменты с соответствующим ID. При повторной диаризации существующие профили сопоставляются с новыми метками по временным пересечениям, но при серьёзно изменившейся разметке результат следует перепроверить.

JSON сохраняет сегменты и speaker metadata; SRT/VTT могут содержать speaker labels. В редакторе новые сегменты добавляются по мере распознавания инкрементально, чтобы не пересоздавать весь текст и не сбрасывать позицию чтения.

## 7. Meeting Intelligence

Режим **«Структурированный протокол с тайм-кодами»** передаёт языковой модели segment ID, время начала/окончания и speaker ID. После ответа проверяются ссылки на реальные сегменты. Неизвестные сегментные и speaker ID удаляются, а пункты без источников помечаются как неподтверждённые.

ИИ — дополнительный слой; для обычной транскрибации и диаризации он не нужен. Внешний API получает текст только при выборе соответствующего провайдера. Для полностью локального анализа используйте Ollama и загруженную локальную LLM.

## 8. Ограничения и испытания

- pyannote Community-1, PyTorch/Torchaudio/TorchCodec и CUDA требуется проверить на конкретной Windows-конфигурации.
- Скорость диктовки, RTF, WER/CER и DER нельзя утверждать без измерений на целевом компьютере и проверенной разметки.
- Точное ручное разрезание и сдвиг границ на waveform-таймлайне — следующий этап Speaker Studio.
- Глобальный поиск по всем встречам и база решений между проектами — направление 3.4, не полный функционал 3.0.8.
