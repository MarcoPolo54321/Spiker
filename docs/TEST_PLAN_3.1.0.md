# План тестирования СПИКЕР 3.1.0

## 0. Новые локальные функции 3.1.0

1. Проверить файлы `models/diarization/sherpa-onnx-pyannote-segmentation-3-0/model.onnx` и `wespeaker_en_voxceleb_resnet34.onnx`; диаризация работает offline без HF-токена.
2. Прогнать `scripts/validate_upgrade.py`: контрольный публичный разговор должен дать два голоса; синтетический русский диалог — одинаковые метки в повторных фразах.
3. Распознать русскую запись faster-whisper Medium с word timestamps и проверить привязку реплик к временным словам.
4. Создать WAV голосами Irina/Ruslan и проверить их карточки лицензий перед публичным распространением.
5. Отправить точный контрольный запрос через встроенный GigaChat; проверить, что сервер слушает только loopback и останавливается при закрытии.
6. Проверить регистрацию микрофонов и уровень во время реальной речи на микрофоне; сохранить текст и заново открыть приложение.
7. Начать распознавание, нажать закрытие окна и убедиться в сохранении очереди/черновика и завершении приложения.
8. Собрать Android APK, установить на физическое ARM64-устройство и проверить микрофон, загрузку/распознавание аудио, разделение голосов и оба синтезатора.

## 1. Сборка и чистая установка Windows

1. На Windows 10/11 x64 установить Python 3.11 x64 и Inno Setup 6.
2. Запустить `Build_Spiker_Windows_Installer.bat` или workflow GitHub Actions.
3. Проверить `Spiker-Setup-3.1.0.exe`, Portable ZIP и `SHA256SUMS.txt`.
4. Установить в чистый профиль пользователя; проверить запуск без отдельной установки Python.
5. Проверить наличие встроенных Whisper Small и T-one; проверить базовую транскрибацию/диктовку offline.
6. Проверить faster-whisper runtime и отдельную установку локальной faster-whisper модели.

## 2. Регрессия транскрибации из логов 3.0.7.6

1. Добавить MP3 и MP4 в очередь.
2. Выбрать faster-whisper Small CPU/INT8 (или Авто при установленной модели).
3. Запустить транскрибацию и убедиться, что первый callback не вызывает `NameError: _format_duration is not defined`.
4. Убедиться, что ошибки UI callback логируются, но не останавливают декодирование.
5. Дождаться конца, проверить число сегментов, текст, прогресс и восстановление после перезапуска.

## 3. Аудиопрофили и дорожки

1. WAV: проверить profile `Сохранить звук` — без VAD/normalization.
2. Речевая запись: `Речь` — проверить выбранный VAD.
3. Длинное совещание: `Совещание` — проверить segmentation и тишину.
4. Музыкальный файл с вокалом: `Музыка и пение` — убедиться, что VAD не удаляет значительную часть аудио.
5. MP4/MKV с двумя аудиодорожками: выбрать индекс 0 и 1, убедиться, что слышимое/распознанное содержимое соответствует выбранной дорожке.

## 4. Диаризация

1. Войдите в Hugging Face, примите условия модели pyannote Community-1 (`pyannote/speaker-diarization-community-1`) и создайте Read-токен.
2. Запустите `Install_Speaker_Diarization.bat`, проверьте установку pyannote.audio 4.0.7 и локальную загрузку Pipeline.
3. Обработайте запись с 2–3 говорящими; проверьте автоматическое создание профилей без ИИ.
4. Проверьте назначение по реальному временно́му перекрытию; без пересечения реплика должна остаться «Не определён», а не получить ближайшего спикера.
5. Проверьте сегменты, где быстрее-whisper вернул word timestamps: смена голоса должна разделять сегмент на границе слова.
6. Проверьте перебивания; overlap metadata должны сохраняться, а не сводиться к одному участнику без следа.
7. Переименуйте профили, повторно выполните диаризацию и проверьте сохранение сопоставления по временным пересечениям.
8. Отмените задачу до запуска и во время inference; в frozen build внешний helper должен завершиться по отмене. Source mode может завершить текущий native inference перед остановкой.

## 5. Очередь и редактор

1. Импортировать старый `queue.json` в SQLite.
2. Запустить 10+ задач и убедиться, что сохраняются статус, сегменты, имена участников и таймкоды.
3. Проверить очередь из более 1000 задач (SQLite delete path не должен упираться в лимит SQL placeholders).
4. При добавлении новых сегментов читать текст в середине документа: scroll position и selection не должны прыгать к началу.
5. Заменить исходный файл другим содержимым по тому же пути; возобновление старых сегментов должно быть заблокировано предупреждением.
6. Проверить паузу, «остановить и сохранить», «прервать и сбросить», перезапуск и целостность БД.

## 6. ИИ и Meeting Intelligence

1. Запустить обычный summary и meeting протокол — убедиться, что AI остаётся отдельной необязательной операцией.
2. Запустить «Структурированный протокол с тайм-кодами» на транскрипте со speaker IDs.
3. Проверить, что каждый источник ссылается на существующий `SEGMENT_ID` и исходный таймкод.
4. Проверить, что неизвестные ID сегментов и speaker IDs не показываются как подтверждённые атрибуции.
5. Проверить, что ответственный и срок не выдумываются при отсутствии сведений в записи.

## Границы автоматических проверок

Unit tests и smoke-test сборки не измеряют реальный DER/WER/CER, качество русской речи, поведение GPU/CUDA, работу микрофона и фактическую точность pyannote. Для этого нужен Windows ПК и набор записей с проверенной вручную разметкой. GitHub Actions собирает EXE на Windows runner, но релиз всё равно следует проверить на чистой машине.


## Регрессия сборщика 3.1.0

1. Удалить только `.build-venv` и запустить `Build_Spiker_Windows_Installer.bat`: окружение должно создаться с `--without-pip`, pip — успешно установиться.
2. Повторить на тестовой копии проекта с частичным `.build-venv` (папка существует, `Scripts\python.exe` отсутствует): скрипт должен удалить неполную среду и создать её заново.
3. Смоделировать отсутствие pip при существующем `.build-venv\Scripts\python.exe`: сборщик должен попробовать `ensurepip`, а при неудаче PyPA get-pip bootstrap.
4. Убедиться, что `Pillow` устанавливается из `res/requirements-test.txt` до запуска unittest и тест `test_training_utility_button_uses_same_transparent_style_as_settings_and_help` проходит.
5. Проверить, что GitHub CI test workflow также устанавливает `res/requirements-test.txt`.
6. Убедиться, что файлы Setup и Portable называются с версией из `VERSION` (`3.1.0`), а Windows VERSIONINFO получает `3.1.0.0`.
