# Архитектура и дорожная карта СПИКЕР 3.0.8 → 3.4

## Текущая архитектура

СПИКЕР разделяет аудиоподготовку, распознавание, диаризацию, хранение транскрипта, интерфейс редактора и ИИ-анализ. Это позволяет независимо включать локальные движки и сохранять основную очередь без обязательного обращения к ИИ.

### Поток обработки файла

1. Media input / FFmpeg: выбор аудиодорожки, декодирование, профиль аудио.
2. ASR: Whisper.cpp или faster-whisper/CTranslate2; streaming ASR Sherpa-ONNX/T-one для диктовки в реальном времени.
3. Diarization: локальный pyannote Community-1, обычная диаризация для перекрытий и exclusive-представление для сопоставления с текстом.
4. Segment alignment: временные метки сегментов и слов faster-whisper; распределение speaker ID при достаточном временном перекрытии.
5. Transcript Core: текст, таймкоды, speaker ID, оценки уверенности, overlap metadata и пользовательские исправления.
6. Queue storage: SQLite/WAL как основное хранилище и JSON для legacy import/backup.
7. Presentation / exports: редактор, участники, воспроизведение, TXT/DOCX/SRT/VTT/JSON.
8. Meeting Intelligence: структурированный протокол, темы, решения, задачи и открытые вопросы с segment ID как ссылками на исходную запись.

## Принципы

- Обычная транскрибация и диаризация не требуют ИИ-провайдера.
- Все тяжёлые компоненты optional и локальны после первичной установки.
- Не назначать спикера по принципу «ближайший временной интервал», если реальное перекрытие недостаточно.
- Любое решение, задача или ответственный из ИИ должны ссылаться на конкретные исходные сегменты; отсутствие источника должно быть явно помечено.
- Пользовательское имя участника не должно зависеть от внутренней метки, которую pyannote назначил при новом запуске.
- После сбоя/перезапуска не терять уже сохранённые сегменты и пользовательские правки.

## Реализовано/укреплено в 3.0.8

- Исправление regression `_format_duration` и изоляция ошибок UI callback от ASR.
- SQLite/WAL queue store, миграция legacy JSON, per-task hash и fingerprint исходного медиа.
- Инкрементальное добавление сегментов в редактор без полной перерисовки документа.
- Audio profile: speech / meeting / music / preserve; выбор индекса аудиодорожки.
- CUDA OOM fallback to CPU в безопасном сценарии.
- Проверка полной локальной модели pyannote и импорта runtime; установщик pyannote.audio 4.0.7 с Hugging Face gated login.
- Диаризация оставляет неуверенные интервалы неопределёнными, поддерживает словесное деление по смене голоса и сохраняет overlap candidates.
- Структурированный ИИ-протокол с segment IDs, временными метками и проверкой источников/ID говорящих.
- GitHub Actions Windows release: Setup.exe + Portable ZIP + SHA256; faster-whisper/CTranslate2 runtime и Sherpa/T-one входят в релизный build.

## Дорожная карта

### 3.1 — Performance

Следующие задачи:
- Короткий real-world benchmark RTF на конкретном устройстве.
- Динамический batch с использованием свободной, а не общей VRAM.
- Очередь GPU-ресурсов между ASR и pyannote.
- Повтор на CPU при OOM, в том числе аккуратное восстановление частичных результатов.
- Интеграционные long-running тесты 60–90 минут.
- Метрики latency, RTF, RAM, VRAM и скорости обновления редактора.

### 3.2 — Speaker Studio

Следующие задачи:
- Waveform/timeline редактор границ реплик.
- Синхронное выделение реплики и слова при воспроизведении.
- Разделение одного сегмента, объединение и переназначение нескольких интервалов.
- Полноценное отображение пересекающейся речи двух участников.
- Устойчивое сопоставление пользовательских профилей при повторной диаризации.
- История правок и откат speaker assignments.

### 3.3 — Recognition Quality

Следующие задачи:
- Forced alignment / WhisperX совместимая модель для русского языка после отдельной проверки.
- Словарь терминов и подсказки per-project.
- Поиск low-confidence и suspicious regions.
- Контроль WER/CER на проверенной русскоязычной тестовой коллекции.
- Сравнение Small, Medium, Large-v3 Turbo и Large-v3.
- Сравнение профилей шумоподавления без удаления согласных/окончаний.

### 3.4 — Meeting Intelligence

Следующие задачи:
- Глобальный поиск по всем встречам и проектам.
- База договорённостей, решений и задач с историей статуса.
- Сводки по каждому участнику между несколькими встречами.
- Дедупликация задач и связывание follow-up встреч.
- Подтверждения для фактов/решений и ручное одобрение протокола.
- Экспорт DOCX/Markdown с таймкодами, ссылками на сегменты и сводными таблицами.

## Критерии приёмки

Релиз не считается готовым только по прохождению unit tests. Требуются:

- Unit + integration tests.
- Windows packaged smoke test.
- Проверка чистой установки и запуска без системного Python.
- Реальное ASR на WAV/MP3/MP4, включая длинный файл.
- Реальная локальная загрузка pyannote Community-1 после принятия условий.
- Ручная эталонная разметка для оценки WER/CER/DER.
- Проверка отмены, восстановления и корректности SQLite после аварийного завершения.
