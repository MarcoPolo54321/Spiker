# Техническое задание — СПИКЕР 3.0

**Статус документа:** спецификация реализуемой версии и план последующих выпусков.  
**Платформа:** Windows 10/11 x64, Python 3.11 x64.  
**Целевой компьютер:** 16 ГБ ОЗУ, дискретная видеокарта с 8–12 ГБ VRAM.  
**Ключевой принцип:** распознавание аудио и ИИ-обработка должны работать локально без интернета после предварительной установки ПО, зависимостей и моделей. Облачный API — дополнительный режим, который включается только по выбору пользователя.

## 1. Цель продукта

СПИКЕР 3.0 — настольное приложение для Windows, объединяющее транскрибацию аудио/видео, диктовку с микрофона, редактирование текста, субтитры и последующую обработку расшифровки языковой моделью. Оригинальные медиафайлы не изменяются. Оригинальная расшифровка и результат ИИ хранятся раздельно.

## 2. Обязательные требования релиза 3.0

### 2.1. Надёжность приложения

- Главный экран открывается без предварительной загрузки Whisper, Vosk, Ollama или облачных SDK.
- Тяжёлые операции выполняются в фоновых потоках и не должны блокировать интерфейс.
- Ошибки распознавания, API, отсутствия модели, недоступности микрофона, повреждённого файла и недостатка места отображаются понятным сообщением; технические детали доступны в журналах.
- Очередь, состояние заданий, частичный текст, прогресс, контрольная точка и временные сегменты сохраняются атомарно в `data/queue.json`.
- После перезапуска незавершённая задача становится «Приостановлено» при наличии подтверждённой контрольной точки, иначе возвращается в очередь с начала.
- Сбой ИИ-обработки не изменяет состояние очереди транскрибации и не теряет оригинальный результат.
- Удаление задания из списка не удаляет исходный аудио-/видеофайл и не должно незаметно удалять экспортированные результаты.

### 2.2. Очередь транскрибации

- Приём одиночных и нескольких файлов, перетаскивание файлов в окно, защита от повторного добавления одинакового пути.
- Форматы входа — по возможностям FFmpeg; список поддерживаемых форматов указан в справке.
- Отображение статуса, прогресса, имени, формата и доступных медиафактов.
- Отдельные действия: «Пауза/Продолжить», «Остановить и сохранить», «Отменить задачу», «Продолжить/повторить», «Удалить из списка».
- Возобновление от последней сохранённой контрольной точки с небольшим перекрытием аудио; устранение очевидного дублирования на стыке.
- При повторном запуске разрешено повторное преобразование исходного контейнера, если временный подготовленный PCM ещё не закэширован. Оптимизация повторного использования PCM — целевое улучшение; корректность имеет приоритет перед скоростью.
- Исходный файл никогда не перезаписывается.

### 2.3. Диктовка

- Отдельный поток записи и отдельный контекст распознавания от файловой очереди.
- Выбор установленного движка/модели для диктовки, если она доступна; промежуточный текст визуально отличается от подтверждённого.
- Управление записью, индикация состояния и понятное сообщение об отсутствии устройства/входящего сигнала.
- Предупреждение об увеличении потребления памяти при параллельном запуске двух тяжёлых моделей.
- После штатной остановки результат сохраняется; закрытие приложения во время активной записи не должно молча уничтожать сессию.

### 2.4. Плеер и редактор

- Сохранение существующего оформления Deep Blue Glass и бренда «СПИКЕР».
- Воспроизведение/пауза, остановка, позиция, громкость, скорость, перемотка и настоящая амплитудная волна.
- Редактирование завершённой расшифровки и отложенное автосохранение в основной TXT-результат; явный экспорт копии.
- Оригинальная расшифровка и результат ИИ не смешиваются. Повторная ИИ-обработка не заменяет оригинал.
- Временные отметки сохраняются как сегменты Whisper с началом, концом и текстом. Субтитры не должны создаваться из расчётных времён по длине всего текста.

### 2.5. Экспорт

Обязательные форматы:

- **TXT** — чистый текст.
- **MD** — текст с заголовком и абзацами.
- **SRT** и **VTT** — только если присутствуют сегменты с реальными временными отметками.
- **JSON** — источник, полный текст, временные сегменты и метаданные результата.
- **DOCX** — редактируемый документ Word.

Если временных отметок нет, экспорт SRT/VTT должен завершиться понятным сообщением, а не создавать ложные субтитры. Временные отметки относятся к исходной временной шкале файла, в том числе после возобновления распознавания.

### 2.6. ИИ-провайдеры

#### Локальный провайдер — обязателен

- Интеграция с Ollama через локальный OpenAI-совместимый Chat Completions endpoint.
- Значение по умолчанию: `http://127.0.0.1:11434/v1`; можно изменить адрес.
- Проверка доступности локального сервера и списка уже установленных моделей.
- Возможность указать имя модели вручную.
- Приложение не загружает модели автоматически и не требует интернета для отправки локального запроса после установки модели.
- Ошибка локального провайдера должна сообщать, что проверить: запущен ли Ollama, установлен ли выбранный тег модели, доступен ли endpoint.

#### Внешний API — дополнительный

- Настраиваемые базовый URL, модель и API-ключ для OpenAI-совместимых поставщиков.
- Ключ не сохраняется в `data/settings.json`, текстовых логах или ZIP-архиве; используется системное хранилище учётных данных через `keyring`, если оно доступно.
- Если системное хранилище недоступно, ключ не записывается в открытом виде на диск.
- Перед отправкой содержимого во внешний сервис требуется явное подтверждение пользователя.
- Ошибка сети, авторизации, лимита или ответа модели не должна менять исходную расшифровку.

#### Сценарии обработки

- Исправление пунктуации, абзацев и очевидных ошибок распознавания с сохранением смысла.
- Краткое содержание.
- Подробный тематический конспект.
- Протокол встречи с решениями и открытыми вопросами.
- Извлечение задач, сроков и ответственных с пометкой «Не указано», когда данных недостаточно.
- Ответ на вопрос по тексту.
- Пользовательская инструкция.

#### Длинные записи

- Разбиение текста на фрагменты по границам абзацев/предложений, затем по словам.
- Отображение количества/стадии обработки и возможность отменить работу между запросами.
- Для длинного текста отдельная агрегация результатов фрагментов; объединение не должно выдавать отсутствующие факты за подтверждённые.
- Оригинал сохраняется неизменным. Результат автоматически сохраняется в `results/ai/` и может быть экспортирован отдельно.

### 2.7. Производительность и совместимость с целевым ПК

- Конфигурация по умолчанию ориентирована на 16 ГБ RAM и 8–12 ГБ VRAM: начинать с небольшой/средней квантованной локальной языковой модели и проверять расход памяти на конкретной системе.
- Не обещать ускорение Whisper на GPU, пока используемый `pywhispercpp` backend настроен в CPU-режиме. Ollama может задействовать поддерживаемую видеокарту для языковой модели, если установленные драйверы и runtime это позволяют.
- На одном ПК одновременно распознавание речи и LLM могут конкурировать за RAM/VRAM. Пользователь должен иметь возможность сначала завершить транскрибацию, затем запускать тяжёлую ИИ-обработку.
- Стартовый экран и переключение между разделами не должны ждать загрузки больших моделей.

### 2.8. Настройки, логи и данные

- Настройки распознавания и ИИ хранятся в `data/settings.json`; секреты API в этот файл не записываются.
- Очередь и контрольные точки — `data/queue.json`.
- Основные результаты — `results/`; ИИ-история — `results/ai/`; журналы — `logs/`.
- Перед первым запуском в новой среде допускается установка библиотек через `Launch_Spiker.bat`. После подготовки приложения и моделей локальный режим должен функционировать без сети.
- Не включать веса моделей, кэш и пользовательские аудиофайлы в дистрибутивный ZIP.

## 3. Критерии приёмки обязательного релиза

1. Все Python-модули проходят компиляцию `py_compile`.
2. ZIP проходит проверку целостности, не содержит веса моделей, пользовательские данные, логи с содержимым расшифровок или виртуальное окружение.
3. Из очереди можно отправить непустой результат в ИИ-панель; результат возвращается в отдельном редакторе.
4. Локальный режим не требует API-ключа и вызывает только локальный адрес, указанный пользователем.
5. API-режим требует ключ, показывает подтверждение отправки и сообщает ошибку без потери исходного текста.
6. При недоступности модели GUI остаётся отзывчивым; диагностика объясняет, что соединение не установлено.
7. Правка готового текста сохраняется в основной TXT-файл и не изменяет временные отметки аудио.
8. Экспорт SRT/VTT использует реальные временные отметки сегментов и корректный формат миллисекунд.
9. Тесты экспорта и разбиения текста проходят на коротких и длинных входах; проверяется отсутствие пустых фрагментов и пропуска содержимого.
10. На целевой машине выполняется ручной smoke-test: WAV/MP3/MP4, диктовка, остановка/продолжение, закрытие/открытие приложения, локальная ИИ-обработка и API-обработка (при наличии ключа).

## 4. Функции следующих версий

- Визуальное сопоставление выделенной фразы с текущей позицией плеера и подсветка активного сегмента.
- Улучшенный кэш подготовленного PCM-аудио, валидируемый по пути/размеру/времени изменения/хэшу исходника.
- Папки, массовые действия, фильтрация и сортировка очереди, история поисковых запросов.
- Словари имён и специальных терминов, если движок распознавания поддерживает подсказки.
- Разделение говорящих (diarization) и редактирование меток говорящих.
- Расширенная аналитика: темы, аргументы, сравнительные таблицы, вопросы/ответы со ссылками на временные сегменты.
- Локальная база знаний по наборам расшифровок (поиск/RAG) с явным индексированием и возможностью удаления индекса.
- Более глубокая аппаратная диагностика, рекомендации моделей по доступной VRAM/RAM и автоматическая проверка контекста модели.
- Установщик Windows, версионирование данных/миграции и безопасное обновление.
- Подписание релиза и интеграционные тесты на реальных Windows-машинах.

## 5. Известные ограничения этого исходного выпуска

- Архив содержит исходный код и интерфейсные ресурсы, но не включает Ollama, веса Whisper/LLM, драйверы или виртуальное окружение.
- Фактический расход VRAM/скорость зависят от модели, квантования, длины контекста и драйверов; это нужно измерить на целевой машине.
- Полноценный end-to-end запуск Qt GUI и реальная транскрибация должны быть проверены на Windows 10/11 с установленными моделями. Статическая проверка исходников сама по себе не заменяет этот приёмочный тест.


## Размещение моделей в 3.0.2

Веса моделей хранятся в корневой папке `models/` (Whisper — `models/whisper/`, Vosk — `models/vosk/`). Код подготовки аудио и распознавания находится в `scripts/transcription/`. Это разные сущности и не должны помещаться в один каталог.
