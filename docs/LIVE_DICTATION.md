# Потоковая диктовка СПИКЕР 3.0.8

В приложении теперь существуют три разных режима ввода с микрофона:

- **Sherpa-ONNX / T-one** — потоковый декодер. Получает короткие PCM-пакеты и сохраняет состояние между ними.
- **Vosk** — резервный потоковый декодер с частичными гипотезами.
- **Whisper** — совместимый режим, который распознаёт короткие окна и имеет более высокую задержку.

## Установка

1. Запустите `Install_Live_Dictation.bat` из корня проекта.
2. Скрипт использует существующее `.venv311` или `.venv`; если окружения ещё нет, создаёт `.venv311` на Python 3.11 x64. Системный Python не используется для установки компонента.
3. Далее скачивается и безопасно распаковывается модель `sherpa-onnx-streaming-t-one-russian-2025-09-08` в `models/sherpa-onnx/`.
4. Откройте СПИКЕР → Настройки → «Модель для диктовки в реальном времени». Выберите «Авто» или «Потоковый Sherpa-ONNX / T-one».

Модель не скачивается во время запуска программы. После установки распознавание выполняется локально. В базовый ZIP не включены runtime sherpa-onnx и веса T-one.

## Как работает live-путь

- Микрофон захватывается в mono PCM16, 16 kHz.
- Для streaming ASR аудио передаётся пакетами по 1600 сэмплов (около 100 мс).
- Один online recognizer и один decoder stream обслуживают всю диктовочную сессию. Для каждого блока не создаётся отдельный WAV.
- Sherpa-ONNX возвращает текущую гипотезу; после endpoint detection фраза фиксируется и состояние распознавания сбрасывается для следующей фразы.
- В редакторе уже зафиксированный текст отображается отдельно от изменяющейся гипотезы (префикс `…`). При остановке фраза финализируется, а временный маркер удаляется.
- Модель загружается до открытия цикла захвата микрофона, поэтому время загрузки не создаёт растущую очередь необработанного аудио.

## Автоматический выбор

Порядок режима «Авто»:

1. T-one, если установлены библиотека и модель.
2. Vosk, если доступна полная локальная модель Vosk.
3. Whisper, если доступна локальная модель Whisper.

Чтобы принудительно использовать другой режим, выберите его в настройках. Сохранённый путь к Whisper-модели не отменяет выбор автоматического T-one/Vosk.

## Буфер и перегрузка

Для T-one используется ограниченная очередь приблизительно до 12 секунд PCM-данных (120 пакетов по 100 мс). Для Whisper-резерва бюджет такой же — шесть окон по 2 секунды. Если декодер длительно не успевает за микрофоном, захват останавливается с явным сообщением; аудио не отбрасывается молча. Устраните нагрузку, уменьшите число фоновых операций или выберите более быстрый компьютер/движок.

## Параметры модели и sample rate

T-one — русская потоковая CTC-модель sherpa-onnx. В опубликованной конфигурации модели указана частота 8 kHz; `OnlineRecognizer` создаётся с sample rate модели 8000 Hz. Микрофон СПИКЕР захватывает 16 kHz PCM, а `accept_waveform` передаёт фактическую частоту исходного аудио для обработки/ресэмплинга на стороне sherpa-onnx. При замене модели обязательно сверяйте sample rate, feature dimension и ожидаемый формат токенов с документацией именно этой модели.

## Сборка Windows с включённым streaming runtime

Публичный GitHub build и `Build_Spiker_Windows_Installer.bat` включают Sherpa-ONNX runtime и локальную модель T-one. Для ручной сборки на Windows с Python 3.11 x64 используйте:

```powershell
.\build_windows.ps1 -WithFasterWhisper -WithLiveDictation -Installer
```

Сборщик установит optional runtime faster-whisper/CTranslate2 и Sherpa-ONNX, загрузит T-one и включит их в portable/installer-пакет. Это увеличивает размер дистрибутива. Проверяйте собранное приложение на чистой Windows 10/11 x64.

## Производительность и критерии тестирования

Пакет 100 мс не означает, что текст гарантированно появляется каждые 100 мс: частота обновления зависит от того, когда модель выдаёт токены и фиксирует гипотезу. Для каждого теста измеряйте:

- capture-to-first-hypothesis latency;
- задержку от конца фразы до endpoint commit;
- real-time factor и отсутствие накопления очереди;
- ошибки слов (WER) на контрольном тексте;
- пропуски/повторы слов при паузах, длинных фразах и остановке записи.

Ориентир для испытаний — первая гипотеза в пределах 0,5–1 секунды и фиксация фразы в пределах 0,8–1,5 секунды после паузы. Это целевые показатели, а не результат, гарантированный для любого оборудования.
